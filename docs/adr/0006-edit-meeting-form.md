# Edit-meeting web form: dedicated /meetings/{id}/edit page, state-dependent fields, cancel via /meetings/{id}/edit/cancel

Every non-Cancelled Meeting on `GET /meetings` gains an **edit** link (`meetingView` gains an `ID` field) leading to a dedicated page at `GET /meetings/{id}/edit`, registered in both `web.NewMux` and the root mux in `main.go` — unregistered paths fall through to `api.NewMux` and 404. The handler loads the Meeting via the store and requires `OwnerID == session user`; a Meeting that is unknown, not owned, Cancelled, or frozen gets a silent 303 to `/meetings` — the list is the canonical set of editable Meetings, and one redirect covers all four rejections. The form is pre-filled from the Meeting and carries only the fields the Meeting's Status allows: **Draft** (no Guests) edits title, start, duration and description; **Scheduled** (has Guests) edits **title and description only**, with start/duration rendered as plain read-only text, not inputs. This restriction is new policy and lives **in the web handler only**: for a Scheduled Meeting the handler ignores any posted start/duration and passes the Meeting's existing values into `EditDetails`; the domain keeps its deliberately status-neutral lifecycle (ADR-0001) and the JSON API keeps accepting full edits. Title remains required (checked in the handler — the domain accepts empty titles, the edge does not, matching ADR-0005), start reuses `parseLocalStart` (`datetime-local`, server-local time), and duration reuses the preset `<select>` of 15/30/45/60/90 — plus one extra `<option selected>` carrying the current value when it isn't a preset, so merely opening and saving the form never silently mutates a duration set via the API. Unlike at creation, **start may move into the past**: the domain's frozen rule is the only edit barrier (ADR-0001), and `/meetings` lists in-progress Meetings, which must stay correctable. Mutations go through `MeetingStore.Update(ctx, id, fn)` — never read-modify-write — so the Postgres row lock keeps them atomic (ADR-0002). `POST /meetings/{id}/edit` saves; on domain rejection the form re-renders with the error text and a 400, mirroring ADR-0005 (error text only, no repopulation). A **Cancel meeting** button on the edit page, guarded by a JS `confirm()`, posts to the dedicated `POST /meetings/{id}/edit/cancel` — deliberately not the API's `POST /meetings/{id}/cancel`, which a web route would shadow for all clients (the ADR-0005 lesson). Success for both save and cancel is a PRG 303 to `/meetings`. Guests are not editable here and nobody is notified; there is no mailer.

## Considered Options

- **Inline editing on the list page**: rejected — a dedicated page mirrors `/meetings/new` (ADR-0005), keeps templates simple, and gives cancel a natural home.
- **Cancel button on the list page, next to edit**: rejected — cancellation is destructive and terminal; keeping it one click deep inside the edit page, behind a `confirm()`, avoids fat-finger accidents.
- **Cancel as an `action=save|cancel` field on `POST /meetings/{id}/edit`**: rejected in favour of a distinct `…/edit/cancel` path — an explicit route per intent reads better than branching on form values.
- **"Scheduled: title/description only" enforced in the domain** (a rule in `EditDetails` or a new mutator, binding the API too): rejected — the lifecycle is intentionally status-neutral (CONTEXT.md, ADR-0001); a web-handler policy is the minimal change and can be promoted to the domain later if it proves to be a real invariant.
- **Enforce future-start on edit, mirroring create**: rejected — the domain deliberately allows past starts on edit; forbidding them would make a listed, in-progress Meeting reject every save.
- **Disabled/locked start & duration inputs for Scheduled Meetings**: rejected in favour of plain text — the form shows only the fields the user is allowed to change.
- **Render a 404 page** for unknown/not-owned/cancelled/frozen Meetings: rejected — a silent 303 to `/meetings` is one code path and leaks nothing about other Users' Meetings; the repo's only not-found page is login-specific.
- **Repopulate the form with submitted values after a validation error**: rejected, consistent with ADR-0005 — error text only; a later UX refinement that doesn't change the design.
- **Web cancel on `POST /meetings/{id}/cancel`**: rejected — it would shadow the JSON API's endpoint at the root mux; dedicated web paths keep HTML and JSON boring.
- **Snap non-preset durations to the nearest preset (or default)**: rejected — a form whose mere opening changes stored data is a bug; the current value is offered as an extra option instead.
